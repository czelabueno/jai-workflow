# Remote modules

A remote module is a module that is exposed as a [Functional API](functional-api.md) or a [MCP Server](mcp.md) and can be accessed from other workflows or applications. This allows for greater flexibility and reusability of modules, as they can be shared across different projects and environments.

## Advantages of using remote modules
- **Reusability**: Remote modules can be reused across different workflows and applications, reducing duplication of code and effort.
- **Scalability**: Remote modules can be deployed in a distributed environment, allowing for better scalability and performance.
- **Interoperability**: Remote modules can be accessed from different programming languages and platforms, allowing for greater interoperability and integration with other systems.
- **Flexibility**: Remote modules can be updated and maintained independently of the workflows that use them, allowing for greater flexibility and agility in development.

## When to use remote modules?
- When you want to create a library of reusable components that can be shared across different projects and environments.
- When you want to create a module that can be used in different workflows and applications, and need to be accessed from different programming languages and platforms.
- When you want to create a module that can be deployed in a distributed environment and need to be accessed from different workflows and applications.
- When you want to create a module that can be updated, tested and maintained independently of the workflows that use them.
- When you want to handle versioning of your modules and need to access different versions of the same module from different workflows and applications.
